# GLM source and accepted-state conditional inputs

The [case plan](source-case-plan.json) covers the same 26 retained GLM sources and their primary observed geometry. Eighteen Flash cases use a separate Sim prefix, `examples/cases/high-concurrency-20261030/glm-source-accepted-26/`; eight full GLM cases remain unchanged. This is input preparation, with no new predictions or raw reads.

Flash A5 cases inherit the reviewed `attention-plus-down` variant; A3 cases inherit `attention-only`. The KDA lowering comes from the explicitly reviewed arch35/arch22 accepted-state prototypes. The state index stride equals that source's observed primary query length. All current queries execute: symbolic accepted counts select the initial state slot, not a fraction of query work. The source's in-kernel sigmoid is an explicit scenario, not evidence inferred from BF16 beta. A private caller applying an external FP32 sigmoid is a different native boundary.

The underlying source, extraction, original case, compatible variant and prototype identities are retained. Hardware and parallel declarations are checked after parsing. Batch comes from the selected Forward geometry: the source called `c3` therefore retains observed B4. Context remains the original conditional input, not cache capacity.

The remaining eight full GLM cases have no KDA body layers. They preserve their original rope, cache and source choices. A Flash rope0/528-byte cache assumption is not applied to their different native contracts.

The initial full-family inventory covered 14 of the 18 Flash sources. Four additional streams now aggregate the original accepted Body windows for A3 c4-livepre/c2/c4 and A5 c96: 165 selected Forwards and 352,181 device events, with 219 source Forwards retained as the wider denominator. They took 54.007 seconds and at most 208.70 MiB, without a new capture or prediction. Their actual/mapping files are under `retained-four-actual/`; the [reprice input index](operator-reprice-inputs.json) now covers all 18 Flash sources. Existing full native KDA buckets can be reused through `glm_kda_accepted_references.py`, which checks all eleven inputs, all three outputs and every retained layer before creating a conditional reference. It does not relax the profiler's strict accepted-token guard.

A metadata-only check of all nine existing A5 KDA buckets selected 10,812 calls without splitting their histograms. Each layer selected one complete-batch source program, keeping every current query. This validates applicability of the explicit conditional declaration, not predicted latency or the captured private kernel flags; cost execution remains a separate next step.

Nine additional complete KDA partitions are now retained under `additional-native-partitions/`: eight A3 Flash sources and A5 c96, 395 Forwards and 13,430 calls. Every eleven-input/three-output ABI bucket retains its whole integer duration histogram and exactly matches the prior full-family actual. The single pass per source took 61.198 seconds, peak 227.81 MiB; independent review passed 474 checks. Combined with the original nine A5 sources, accepted-state references now cover all 18 Flash sources, 713 Forwards and 24,242 KDA calls. These extra partitions cover KDA only; fused up and sparse attention are not extrapolated to the additional sources.
