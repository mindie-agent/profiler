# mindie-profiler 0.5.2

[English](profiler-0.5.2.en.md)

本版本正式交付 Decode / Prefill 结构拆解、实测事件关联与统一离线验证管线，并完整继承 `0.5.1` 的 CLI 帮助文案与诊断错误修复：

- **多源事件与原生张量契约归一化**：统一解析 CSV、SQLite DB 与 JSON Trace 事件，直接复用 `mindie-sim` 声明的模型结构、融合子图与物理资源边界，覆盖 Attention、KV Cache、GDN/KDA、MoE、mHC、残差及融合算子。
- **Decode Body 与逐层边界自动切分**：从真实 `kernel_details.csv` 自动识别完整 Decode Body 与层级边界，分别核算设备活动并集、内部未覆盖间隙、外围模型阶段耗时与 AICPU 控制等待。
- **同构算子群（Cohort）对账准则**：按完整张量契约与物理工作量聚合对账；图模式下缺乏显式层级证据时不猜测具体层号。单次调用耗时 `> 50 us` 采用 `15%` 相对容差，`<= 50 us` 采用 `15 us` 绝对容差。
- **单一回放入口与紧凑外置取证**：以唯一入口 `examples/structure/pipeline.py`、唯一清册 `cases.json` 与 `results/` 取代按日期/提交命名的临时脚本与过程目录。每轮回放统一从固定 `mindie-sim` 包重新预测，逐源完整明细通过 SHA256 指针外置归档，入库 JSON 体积严格小于 `5 MB`。
- **训练/留出边界与物理服务域隔离**：服务域拟合显式记录训练集与留出集源 SHA256、算子实现、数值精度、内存布局与并行边界；跨 TP 或跨并发度不直接复制单点实测耗时，同源样本内校准结果不冒充盲测泛化结论。
- **Prefill 与 Engine 统一验收边界**：Prefill 与 Engine 共用同一管线入口；Prefill 按完整 Chunk 比较 Body 耗时，客户端 TTFT、设备调度周期、MTP/外围区间与 Completion-Token TPOT 各自保留独立边界。Serving 契约未满足或预测超时均显式报告失败，绝不生成伪造 PASS。

当前离线回放结果归档于源码树 `examples/structure/results/`。全部硬件证据均来自既有 A3/A5 采集的离线回放，本版本未启动新设备任务；原始大体积捕获与外置明细不包含在 Git 仓库或发行 Wheel 包中。

原有的 66 个 Decode 基线用例在本次统一回放中全部达标；扩展的跨 TP / 长上下文留出集仍保留未达标案例，算子级通过率不替代整网 Body 精度结论。此外，`mindie-sim 0.8.0` 在导出 DeepSeek-V4.1 DP8 完整结构时实测峰值超出 `512 MiB` 内存预算，相关算子结果已诚实保留资源门禁失败状态（有界索引接口将在后续配套版本交付）。

结构关联与成本对账要求配套安装 `mindie-sim 0.8.0`（发行依赖锁定其正式发布提交）。Release 附件中的基准测试报告记录了精确源码提交、测试结果与实测指标；程序执行成功、证据完备与精度达标三类状态始终分开独立报告。
