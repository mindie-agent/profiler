# mindie-profiler 0.5.17: SSOT Unification on `mindie-sim 0.9.19`, Closed-Form Subgraph Efficiency Attribution, and Multi-Window PMU / Step-Origin Hardening

[中文](profiler-0.5.17.md)

`mindie-profiler v0.5.17` formally pairs with `mindie-sim v0.9.19`, removes roughly 2,890 lines of duplicate definitions, and delegates model catalog geometry, Ascend SKU hardware specifications, and observed communication/kernel contracts to a single source of truth:

- **SSOT Unification with ~2,890 Duplicate Lines Removed**: Model catalog geometry (`sim_bridge_catalog.py`), Ascend SKU hardware peaks and topology (`hardware_presets.py`), and observed communication, fusion, quantization, layout, and kernel contracts (`body_*_contracts.py`, `tensor_contracts.py`, `structure_*`) are no longer mirrored locally; they delegate directly to `mindie_sim.model_catalog`, `mindie_sim.backends.ascend.profiles()`, and `mindie_sim.observed_contracts` from `mindie-sim v0.9.19`. Forwarding modules use PEP 562 `__getattr__` lazy shims, so top-level imports never reach `mindie_sim` and `python -I` stays clean with zero NPU context.
- **Closed-Form Subgraph Efficiency Attribution**: Structure export now uses the shared `mindie_sim.subgraph_math` (`algebraic_cube_flops`, `algebraic_vector_ops`, `minimal_boundary_hbm_bytes`), where `evaluate_subgraph_efficiency` computes subgraph Cube / Vector / HBM efficiency directly from measured cohort `busy_union_ns`, invocation multiplicity, and declared hardware peaks. Missing complete cohorts or peaks are reported honestly as `declared_only` / `unavailable` rather than falling back to local formulas.
- **Multi-Window PMU Isolation and Track 3 Step-Origin Hardening**: `_prime_pmu_cache` now collects `globalTaskId`s per merged, sorted, disjoint window span, so tasks living in gaps between windows no longer consume the PMU scan budget. Small ID sets are filtered in SQL with `IN (...)`, reusing the shared 400-ID bound. CSV `--auto-step` requires an explicit step start timestamp (`Step Start Time(us)`) instead of fabricating window origins from step IDs, and the containment scan is an exact max-end segment tree that preserves input order while avoiding quadratic behavior.
