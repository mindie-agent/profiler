# mindie-profiler 0.5.15

[中文](profiler-0.5.15.md)

This is a storage-lifecycle maintenance release. It fully preserves the `0.5.14` pairing with `mindie-sim 0.9.14`, CANN 9.x steady-state capture, the operator C-ABI catalog, content-addressed single-operator reproducers, cluster interconnect probes, and `ACLGraph` diagnostics. Every change only bounds disk caches, the content-addressed store, and temporary-directory leakage in long-running processes and the test suite; measurement semantics and receipt schemas are unchanged:

- **Bounded CANN 9.x capture-shim cache and compile-timeout cleanup (`mindie_profiler/cann_abi.py`)**:
  - `subprocess.TimeoutExpired` derives from `SubprocessError`, not `TimeoutError`, so the old code bypassed the timeout branch and leaked `.<shim>.tmp.<pid>`; compiler timeouts now surface as the builtin `TimeoutError`, and the unpublished temporary object is deterministically removed in `finally`, leaving only an object that was successfully `os.replace`d.
  - Compilation, publication, and eviction are serialized by one stable `cache_dir/.cann_abi_build.lock` (`flock` on POSIX, `msvcrt.locking` on Windows) plus an in-process thread lock. Per-variant `.*.lock` files are never created or unlinked, so eviction can no longer split concurrent `flock` waiters onto different inodes and let two processes compile the same `.so` at once.
  - Each compile uses a unique `.<shim>.tmp.<pid>.<random token>` name, so two threads in one process cannot collide. Interrupted `*.tmp.*` leaves older than `3600s` are swept only after a non-blocking probe proves no live builder owns the cache. After a successful publish, only the newest `8` `libmindie_cann9_capture_*.so` variants survive by mtime; an `OSError` from a mapped or busy `.so` is ignored instead of downgrading the successful build.
- **Bounded `/tmp/mprof` content-addressed reproducer and diff retention (`mindie_profiler/repro_retention.py`)**:
  - `prune_repro_storage(root, *, max_entries=64, max_age_days=14)` independently bounds CAS slots (`<sha>/repro.py` + `manifest.json`) and diff slots (`diff/<id>/diff.json`). Pruning refuses a `<root>` or `<root>/diff` that is a symlink or Windows reparse point (including NTFS junctions detected through `st_reparse_tag` / `FILE_ATTRIBUTE_REPARSE_POINT`), and skips candidate entries and leaves with the same check.
  - All leaves are pre-validated before anything is unlinked: the directory must contain only known leaf names and every present leaf must be a regular, non-reparse file. A partially damaged slot with a regular `repro.py` and a symlinked `manifest.json` therefore keeps its regular sibling intact.
  - Before writing leaves, a writer publishes a private `.<slot>.write-*` marker under the cross-process `<root>/.retention.lock`, and removes it only after the inodes enter the protected set. Eviction holds both `repro_storage._LOCK` and that OS lock; inside one critical section it re-checks `_SLOTS`, `_REGISTRY`, `_PROTECTED_INODES`, lock/write markers, and leaf inode identities, then atomically `os.replace`s the entry to a private `.trash-*` sibling before releasing the lock. Only re-validated regular leaves are unlinked afterwards; leftover `.trash-*` siblings and write markers older than `3600s` are swept. This removes the check-then-delete TOCTOU across threads and processes without holding the process lock across leaf I/O.
  - Runs opportunistically after each successful `stage_artifacts` delivery; a pruning failure never downgrades the delivered artifact to `delivery_failed`.
- **Atomic trace-sidecar rebuild and single-file publish (`mindie_profiler/sources_trace.py`)**:
  - Every rebuild uses a unique private `.<index>.tmp.<pid>.<random token>` database and takes its `.lock` ownership lock before creating it. `_open_index()` and the whole build/publish run inside `try/finally`, so a PRAGMA failure, `ProfilerSchemaError`, or any interruption always closes the connection and removes the temporary database and its `-wal`/`-shm` siblings.
  - Publication is serialized by a stable `.<index>.lock`. The build database runs `PRAGMA wal_checkpoint(TRUNCATE)`, switches to `PRAGMA journal_mode=DELETE`, closes, and is verified to have no `-wal`/`-shm` (a self-contained single file). It is then published by removing the old main database, removing both old sidecars and verifying their absence, and finally `os.replace`-ing the new database into place.
  - No interruption point leaves **[new database + old WAL]**: a crash after removing the old main database leaves no `index_path`, so the next caller rebuilds cleanly from the raw trace; once `os.replace` completes no stale sidecar exists and ordinary read-only connections can open the index safely.
  - A zombie temporary database is swept only when the newest mtime across `tmp_db`, `tmp_db-wal`, and `tmp_db-shm` is older than `6` hours **and** its ownership lock can be acquired non-blockingly (proving no live build). `PRAGMA journal_size_limit = 8388608` bounds WAL reuse growth after checkpointing; it is **not** a hard cap during an active transaction.
- **Zero leftover test temporary directories (`tests/temp_workspaces.py`, `tests/conftest.py`)**:
  - Adds a process-wide temporary-workspace registry covering `nr4-probe-*` two-thread probe workspaces, the `mpr_` short root, and the `mp_`, `mpc_`, `r6cas-`, `r6sup-`, `r7cas-`, `r10...-`, and `nr_s6_r11root_` `/tmp` roots.
  - A per-test autouse fixture `finally` and process `atexit` both reclaim them. A path is discarded from the registry only after `shutil.rmtree` confirms `not os.path.lexists(path)`, so transient Windows handle contention is retried by the next `atexit` drain; `run_ranks` releases its own workspace immediately on an exceptional exit.
- **Regression tests (`tests/test_storage_lifecycle_contracts.py`)**:
  - Covers symlinked `<root>/diff`, Windows reparse points (detected through `st_reparse_tag` / `FILE_ATTRIBUTE_REPARSE_POINT` after removing `os.path.isjunction`), and partially symlinked slots that must never delete outside the root; a deterministic thread interleaving proves eviction re-checks live registration and never deletes a slot being registered.
  - Covers same-process threaded `cann_abi` builds plus cache eviction that never unlink `.cann_abi_build.lock` or collide on temp `.so`; same-process threaded trace rebuilds with unique temp databases; `>6h` temporary databases that are not swept while a `-wal` is fresh or the ownership lock is held; and fault injection proving an interrupted publish never leaves a [new database + old WAL] pair. It also covers the delayed-retry temporary-workspace registry.
